# astrbot_plugin_subconscious

AstrBot 主动私聊插件。绑定整条私聊会话后，节拍检查聊天是否已经静默；规则允许时，自动读取这条私聊当前选中的对话，用当前主模型、人设和近期历史发起一次临时沙盒请求。模型在沙盒中决定是否主动接话及消息内容，批准后才真正发送。新建、切换或清空内部对话不会解除私聊绑定。

适用于 AstrBot **>=4.29.1,<5**，需要配置聊天模型和支持主动发送的消息平台。插件不依赖额外的 Python 包。

## 工作流程

1. 在目标私聊执行 `/潜意识绑定`，保存真实私聊 UMO（平台实例 ID、消息类型和私聊会话 ID），不固定任何内部对话 ID。
2. 正常聊天。用户或助手最后一次发言后开始计算静默时间，包括说过“拜拜”后进入静默的情况。没有必须匹配的告别关键词。
3. 每次节拍检查北京时间静默时段、每日次数、冷却时间、最小静默时间和连续未回复次数。规则不通过时不请求模型。
4. 规则通过后，通过 `get_curr_conversation_id(umo)` 查找该私聊当前选中的对话，再用 `context.get_current_chat_provider_id(umo)` 和 `context.llm_generate(...)` 请求当前主模型。人设按 AstrBot 的会话人设规则解析，读取当前正常对话的近期可见文本。
5. 单次请求同时判断是否发言及要说什么。模型只返回 `{"action":"skip","message":""}` 或 `{"action":"send","message":"实际对话内容"}`。评估与构思过程不公开。
6. `skip` 时直接丢弃结果；`send` 时再次检查对话是否有新活动，确认结果仍有效后只发送 `message`。发送成功才把这条 assistant 消息追加到正常对话，供之后正常聊天接续。

“审核”是第 3 步的规则检查；是否值得主动接话由第 4–5 步的主模型自行判断。没有额外审核模型或第二轮回复生成请求。普通告别不永久停用主动消息，用户明确的忙碌、休息和不要打扰要求会提供给模型判断；需要确定停止时执行 `/潜意识解绑`。

## 安装与绑定

在 AstrBot 插件管理中通过仓库地址安装或更新：

https://github.com/zzz27578/astrbot_plugin_subconscious

首次安装请在接收消息的私聊中执行 `/潜意识绑定`。从 v0.2.0/v0.2.1 更新到 v0.2.2 时会自动迁移已有绑定，删除旧的固定对话 ID，无需重新绑定。无需填写平台名称或依赖自动猜测；旧配置中的 `target_platform` 不再使用。

首次绑定允许 AstrBot 管理员或配置项 `target_user_id` 指定的用户执行；已绑定用户也可以管理绑定。绑定指令始终绑定发令者所在的私聊。目前仅支持一个绑定，重新绑定会替换原绑定。

例如，`default:FriendMessage:2950506809` 标识同一条私聊；AstrBot 内部对话 ID 会随新建和切换而变化，但 UMO 不变，主动消息继续发到这条私聊。绑定回执和 `/潜意识状态` 会显示实际 UMO，也可通过 AstrBot 的 `/sid` 核对。实际值以事件为准，不能把适配器类型 `aiocqhttp` 当作平台实例 ID 来猜测。

当前没有选中的内部对话或对话已删除时，私聊绑定仍然有效，只等待正常聊天恢复当前对话，不创建沙盒对话、不强制切换内部对话。之后会自动使用新的当前对话，无需重新绑定。

| 指令 | 行为 |
| --- | --- |
| `/潜意识绑定` | 绑定整个当前私聊会话，自动跟随其当前对话 |
| `/潜意识解绑` | 删除绑定，停止主动消息；正在评估的结果也会作废 |
| `/潜意识状态` | 查看绑定是否生效、精确到秒的静默时长、最近计时更新时间与原因、连续未回复次数及节拍 |

静默从最后一次真实用户消息或助手回复计时，转发、图片、语音等媒体消息也会重新计时。例如 15:32:50 收到转发消息，15:34:21 查询时约静默 1 分 31 秒，并非从更早的文字聊天结束开始计算。状态和测试指令、空白或通知事件不重新计时。v0.2.3 起按“小时、分、秒”显示，避免将短于几分钟的静默四舍五入为 `0.0 小时`；同时显示最近计时更新的北京时间及原因。插件重载和重新绑定会从当时重新计时，也会在原因中说明。

常规节拍日志的 `RULE_SKIP` 会附带具体规则原因；静默不足会显示当前和要求时长，主动消息冷却中会显示剩余时间。模型返回沉默仍为 `MODEL_SKIP`，两者含义不同。

## 测试指令

`/潜意识测试 [评估|force] [静默时长] [预览|发送]`

所有测试会跳过第 3 步的时间和频率规则，但仍检查绑定、对话有效性、结果格式以及评估期间的真实聊天活动。普通评估默认只预览决策；`强制`/`force` 模式默认实际发送，也可显式指定 `预览`。预览不显示或保存沙盒草稿。测试与状态控制指令本身不更新活动状态、静默时长或未回复计数。

| 示例 | 行为 |
| --- | --- |
| `/潜意识测试` | 立即调用主模型，用实际静默时间判断；仅报告决策 |
| `/潜意识测试 3` | 模拟静默 3 小时，立即调用主模型；允许模型决定沉默 |
| `/潜意识测试 30m` | 模拟静默 30 分钟；也支持 `3h`、`3小时`、`30分钟` |
| `/潜意识测试 3 发送` | 模拟静默 3 小时，模型批准后实际发送 |
| `/潜意识测试 强制` | 要求模型跳过沉默判定并构思消息，使用实际静默时间；有效结果直接发送 |
| `/潜意识测试 force 3` | 模拟静默 3 小时，强制构思；有效结果直接发送 |
| `/潜意识测试 force 3 预览` | 强制构思但只报告决策，丢弃草稿 |
| `/潜意识测试 force 3 发送` | 强制构思并在返回有效 `send` 结果后实际发送 |

强制构思只修改测试提示词，不把异常、空回复或非法输出当作消息发送。即使模型不遵守强制提示而返回 `skip`，也不会伪造消息。

结果会明确区分 `MODEL_SKIP`（已调用模型，模型沉默）、`APPROVED`（预览批准）、`SENT`（已发送）、`RULE_SKIP`（规则阻止调用）、`ERROR`（调用或格式校验失败）、`LLM_TIMEOUT`、`SEND_FAILED`、`SENT_HISTORY_FAILED`、`STALE`（当次评估期间对话变化，结果已丢弃）、`BUSY`、`UNBOUND`、`WAITING_CONVERSATION`（私聊已绑定，等待正常聊天建立当前对话）和 `CONVERSATION_MISSING`（当前对话暂不可用）。错误不再显示为“模型决定 SKIP”。

## 配置

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `target_user_id` | 空 | 可选的指令授权用户；管理员和已绑定用户也可操作 |
| `tick_interval_minutes` | 60 | 节拍间隔，单位分钟，带少量随机浮动 |
| `max_daily_proactive` | 0 | 每日主动发送上限；0 表示不限次数 |
| `min_interval_hours` | 2.0 | 两次实际主动发送之间的冷却时间 |
| `min_silence_hours` | 1.5 | 用户或助手正常发言后最小静默时间 |
| `max_unanswered_pings` | 3 | 用户未回复时最多连续主动发送次数 |
| `history_messages` | 20 | 请求使用的最近正常对话文本消息条数 |
| `llm_timeout_seconds` | 120 | 单次沙盒请求超时时间 |
| `persona_prompt` | 空 | 可选语气补充；自动沿用当前对话人设 |

北京时间 00:00–07:00 不执行常规沙盒请求。插件加载后首次节拍约为 60 秒，但最小静默时间仍会阻止刚启动就发言。规则计数与最后交互时间仅保存在内存中，重载后重新计时。只有实际发送成功才增加每日计数和未回复计数，预览或模型沉默不增加。

## 沙盒与数据

- 沙盒是一次独立、非流式、无工具的模型请求，不是新的持久对话，也不是执行代码的安全容器。
- 不进入普通聊天的 agent/tool 循环，不触发普通 LLM 插件钩子，不加载工具、检索或长期记忆扩展。继承的是当前会话的主模型、有效人设（含示例对话）和近期可见聊天文本。
- 历史文本在请求中临时复制：每条最多 4000 字，总历史文本最多 24000 字。忽略图片、工具消息和独立推理内容。
- 提示词、上下文副本、模型响应、`reasoning_content`、未发送草稿和沉默结果不写入插件 KV、文件或正常对话历史，不挂到事件对象，也不记录到插件日志。请求结束或超时后释放引用。Python 对象释放不承诺内存物理擦除。
- 插件持久化的只有绑定路由元数据：UMO、用户 ID。不保存固定内部对话 ID。解绑会删除这些绑定数据。
- 成功发出的消息属于真实聊天，只以普通 assistant 消息写回正常对话；不保存沙盒 JSON、判断提示词或思考过程。
- 最近对话和人设会发送给配置的模型服务。模型服务自身的数据策略及 AstrBot/Provider 的底层调试日志或观测记录由相应服务与配置控制，插件不能代其保证零留存。

发送前使用 AstrBot 的会话锁复核当前对话 ID 和正常历史，避免把旧上下文生成的消息发到新对话。模型请求期间不占用正常聊天锁；用户发来真实文字、图片、语音等消息、正常助手回复、切换对话或解绑时，未发送的评估结果会作废。切换对话只丢弃当次结果，私聊绑定不受影响，下次节拍或测试自动使用新对话。发送成功后写回的是当次评估所用的正常对话，避免混入其他对话。

OneBot 通知、请求、输入状态、机器人自身消息及空白事件不算用户发言，不会重置静默时间或触发 STALE。强制测试也遵循真实聊天活动保护。重叠的节拍/测试不会重复发起沙盒请求。
